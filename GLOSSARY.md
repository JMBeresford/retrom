# Ubiquitous Language & Domain Glossary

This glossary defines the authoritative vocabulary for the Retrom ecosystem. AI agents and
developers must strictly adhere to these definitions across all source code, API contracts, variable
naming conventions, and documentation.

## Emulation & State Boundaries

### Save State

- **Definition**: A complete snapshot of the emulated console's volatile memory (RAM, CPU state,
  VRAM) captured at a precise millisecond in time.
- **Source Code Naming**: Must use `SaveState`, `saveStateId`, or `save_state`.
- **Forbidden Synonyms**: Never use `SaveFile`, `SRAM`, `NativeSave`, or `InMemorySave`.
- **Implementation Rule**: Handled as immutable, large binary blobs representing freeze-frame
  execution points.
- **Implementation Rule**: A save state for one emulator (or _version_ of an emulator) is not
  guaranteed to be compatible with another emulator or version. In general, expect incompatibility
  across different emulators and versions.

### Save File

- **Definition**: The persistent, on-disk file generated by the emulated game's native saving
  mechanism (e.g., standard in-game battery backup, memory card file, or SRAM writes).
- **Source Code Naming**: Must use `SaveFile`, `saveFileId`, or `save_file`.
- **Forbidden Synonyms**: Never use `SaveState`, `StateSnapshot`, or `FreezeFrame`.
- **Implementation Rule**: Handled as mutable files or file streams that sync periodically when the
  client detects an in-game save action.
- **Implementation Rule**: A save file for a given **platform** is generally compatible across all
  emulators that support that platform, but not necessarily across different platforms. In general,
  expect incompatibility across different platforms and compatibility across different emulators and
  official hardware.

## Library & Platform Semantics

### Platform

- **Definition**: The target hardware architecture or operating system environment a game was
  originally designed to run on (e.g., Nintendo Entertainment System, Sony PlayStation 2, Windows).
- **Source Code Naming**: Must use `Platform`. Never use `Console`, `System`, or `Architecture`
  interchangeably.

### Library

- **Definition**: A collection of platforms and their respective games, organized for discovery,
  emulation, and management within the Retrom ecosystem. Associated with a single server-local root
  directory on disk.
- **Source Code Naming**: Must use `Library`. Never use `Collection`, `Repository`, or `GameSet`
  interchangeably.
